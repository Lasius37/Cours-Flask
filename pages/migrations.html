    Comprendre les migrations

    La structure d'une base de données dépend des modèles définis dans l'application. Lorsqu'un modèle est modifié, la base de données existante n'est pas mise à jour automatiquement. Par exemple, le modèle suivant peut initialement contenir deux colonnes : 

    class Book(db.Model):
    id = db.Column(...)
    title = db.Column(...)

    Si une nouvelle colonne est ensuite ajoutée : 

    class Book(db.Model):
    id = db.Column(...)
    title = db.Column(...)
    publication_year = db.Column(...)

    la table déjà présente dans la base ne contient toujours que les anciennes colonnes.

    Une migration décrit une évolution de la structure de la base de données. Elle peut notamment permettre :

    • d'ajouter ou de supprimer une table
    • d'ajouter ou de supprimer une colonne
    • de modifier certaines propriétés d'une colonne
    • d'ajouter une clé étrangère
    • de créer une table d'association

    Pour cela, il est nécessaire d'utiliser Flask-Migrate.

    Installer et configurer Flask-Migrate

    Installer Flask-Migrate dans l'environnement virtuel du projet : 

    pip install Flask-Migrate

    Ajouter ensuite la dépendance au fichier requirements.txt : 

    pip freeze > requirements.txt

    On peut alors créer l'extension dans le fichier app/extensions.py. 

    from flask_migrate import Migrate
from flask_sqlalchemy import SQLAlchemy


db = SQLAlchemy()
migrate = Migrate()

    Les deux extensions sont ensuite initialisées dans create_app(). Dans app/__init__.py : 

    from flask import Flask

from .extensions import db, migrate


def create_app():
    app = Flask(__name__)

    app.config["SQLALCHEMY_DATABASE_URI"] = \
        "sqlite:///database.db"

    db.init_app(app)

    from . import models

    migrate.init_app(app, db)

    # Enregistrement des blueprints

    return app

    Flask-Migrate reçoit :

    • l'application Flask à utiliser
    • l'objet SQLAlchemy contenant les modèles

    L'import des modèles permet à SQLAlchemy et à Flask-Migrate de connaître les tables attendues.

    Initialiser les migrations

    L'initialisation ne doit être réalisée qu'une seule fois pour le projet. Depuis la racine du projet : 

    flask --app app db init

    L'option --app app indique à Flask que l'application se trouve dans le package app.

    Flask détecte alors la fonction create_app(). La commande crée un dossier migrations à la racine du projet. Il contient la configuration et l'historique des évolutions de la base de données. 

    project/
│
├── app/
├── instance/
├── migrations/
│   ├── versions/
│   ├── env.py
│   ├── README
│   └── script.py.mako
│
├── run.py
└── requirements.txt

    Le dossier migrations fait partie du projet. Il doit être conservé et ajouté au dépôt Git.

    Créer et appliquer une migration

    Après avoir créé ou modifié les modèles, générer une migration : 

    flask --app app db migrate -m "Création des tables initiales"

    Le paramètre -m permet d'ajouter un message décrivant la modification.

    La commande compare :

    • les modèles actuellement définis dans le code
    • la structure actuelle de la base de données

    Elle crée ensuite un fichier dans migrations/versions/. Son nom contient un identifiant unique et le message de la migration : 

    3a42f82d51c0_creation_des_tables_initiales.py

    Une migration contient principalement deux fonctions :

    Fonction Rôle
    upgrade() Faire évoluer la base vers cette version
    downgrade() Annuler les opérations de cette version

    La commande migrate crée un fichier, mais elle ne modifie pas encore la base de données.

    Avant d'appliquer une migration, ouvrir le fichier généré et vérifier les opérations présentes dans upgrade() et downgrade(). Appliquer ensuite toutes les migrations qui ne le sont pas encore : 

    flask --app app db upgrade

    La structure de la base de données est alors mise à jour. Flask-Migrate enregistre également dans la base la version actuellement appliquée. Toutes les modifications de la base suivent le même processus, ce qui crée à chaque migration un nouveau fichier.

    Consulter l'état des migrations

    Plusieurs commandes permettent d'observer l'état du système de migrations.

    Commande Résultat
    flask --app app db current Afficher la version actuellement appliquée
    flask --app app db history Afficher l'historique des migrations
    flask --app app db show head Afficher les informations sur la dernière migration
    flask --app app db check Vérifier si les modèles contiennent des modifications non migrées

    La commande suivante affiche l'ensemble des commandes disponibles : 

    flask --app app db --help

    Annuler une migration

    Il est possible de revenir à la version précédente : 

    flask --app app db downgrade

    Flask-Migrate exécute alors la fonction downgrade() de la dernière migration appliquée.

    Pour revenir à une version précise : 

    flask --app app db downgrade identifiant_revision

    Une migration annulée peut de nouveau être appliquée : 

    flask --app app db upgrade

    Utiliser une base existante

    Une difficulté peut apparaître lorsque l'application possède déjà une base créée avec db.create_all(). Si les données ne doivent pas être conservées pendant le développement, la solution la plus simple consiste à :

    • supprimer la base de développement
    • initialiser Flask-Migrate
    • créer la migration initiale
    • appliquer cette migration
    flask --app app db init
flask --app app db migrate -m "Migration initiale"
flask --app app db upgrade

    Si la base contient des données à conserver, elle ne doit pas être supprimée. Il faut d'abord créer un historique correspondant à sa structure actuelle. La commande suivante peut indiquer qu'une révision est déjà appliquée sans exécuter ses opérations : 

    flask --app app db stamp head

    La commande stamp ne modifie pas la structure de la base de données. Elle ne doit être utilisée que si la base correspond déjà exactement à la révision indiquée.

    Erreurs fréquentes

    • Continuer à utiliser db.create_all() : les tables peuvent être créées en dehors de l'historique des migrations .
    • Oublier d'importer les modèles : Flask-Migrate ne détecte pas les tables attendues .
    • Exécuter les commandes depuis un mauvais dossier : Flask ne trouve pas le package de l'application .
    • Modifier les modèles sans créer de migration : le code et la structure de la base deviennent différents .
    • Confondre migrate et upgrade : la première commande génère un fichier, la seconde modifie la base .
    • Appliquer une migration sans la vérifier : des opérations incorrectes ou incomplètes peuvent être exécutées .
    • Modifier manuellement un ancien fichier de migration déjà partagé : les différents environnements ne possèdent plus le même historique .
    • Supprimer le dossier migrations : l'historique permettant de reconstruire la base est perdu .
    • Utiliser downgrade sans vérifier ses effets : certaines données peuvent être supprimées .
    • Utiliser stamp sur une base dont la structure ne correspond pas à la révision : Flask-Migrate considère à tort que les migrations sont appliquées .
