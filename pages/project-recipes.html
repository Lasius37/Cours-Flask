Projet : le carnet de recettes

    Dans cette page

    • Énoncé
    • Conseils de réalisation

    Énoncé

    Vous devez réaliser une application Flask permettant de gérer un carnet de recettes personnel.

    1. Objectif général

      • L'application permet de gérer les recettes et leur catégorie.
      • Chaque recette fait partie d'une seule catégorie.
      • Chaque catégorie peut contenir plusieurs recettes.
      • L'utilisateur peut consulter les recettes ou les filtrer.
      • L'utilisateur peut ajouter, modifier et supprimer les différentes données.

    2. Données à gérer

      • Une recette est caractérisée par :
        • un nom
        • un temps de préparation
        • un niveau de difficulté
        • une estimation du coût
        • le nombre de personnes pour lesquelles elle est conçue
        • une liste d'ingrédients
        • une série d'étapes de préparation
        • une photo facultative
        • une catégorie
        • un marqueur pour les recettes végétariennes
      • Une catégorie est caractérisée par :
        • un nom
        • une couleur

    3. Relations entre les données

      • Une catégorie peut contenir plusieurs recettes.
      • Une recette fait partie d'une seule catégorie.

    4. Fonctionnement général

      • L'application comporte plusieurs parties :
        • une page d'accueil présentant l'application et donnant accès aux principales fonctionnalités
        • une partie consacrée aux catégories
        • une partie consacrée aux recettes
      • Pour chaque type de donnée, l'application permet au minimum :
        • d'afficher la liste complète des éléments
        • d'afficher les informations détaillées d'un élément
        • d'ajouter un nouvel élément
        • de modifier un élément existant
        • de supprimer un élément après confirmation
      • Les formulaires doivent vérifier les données avant leur enregistrement.
      • Les formulaires de modification doivent afficher les données déjà enregistrées.
      • Les différentes pages doivent permettre de naviguer entre les éléments liés.

    5. Gestion des recettes

      • La liste des recettes permet :
        • de rechercher une recette par son nom
        • de filtrer les recettes par catégorie, par coût, par niveau de difficulté ou par durée de préparation
      • La page détaillée d'une recette affiche :
        • sa catégorie
        • son nom
        • sa photo si elle est donnée
        • son temps de préparation
        • son niveau de difficulté
        • son coût estimé
        • le nombre de personnes pour lesquelles la recette est pensée
        • la liste de ses ingrédients
        • la liste de ses étapes de préparation
        • si elle est végétarienne

    6. Gestion des catégories

      • La liste des catégories permet de rechercher une catégorie par son nom.
      • La page détaillée d'une catégorie affiche :
        • son nom
        • la couleur qui lui est associée
        • la liste des recettes qui en font partie
      • Une catégorie ne peut être supprimée que si elle ne contient aucune recette.

    7. Présentation et navigation

      • Les pages utilisent une structure générale commune.
      • Le menu permet d'accéder aux catégories et aux recettes.
      • Chaque liste donne accès aux pages détaillées correspondantes.
      • La page d'une catégorie donne accès à ses recettes.
      • La page d'une recette donne accès à la catégorie associée.
      • Des liens permettent de revenir facilement aux listes précédentes.
      • Les actions principales sont clairement identifiables.
      • Les messages d'erreur sont compréhensibles.
      • L'affichage reste cohérent dans toute l'application.

    8. Contraintes générales

      • L'application doit être structurée avec plusieurs blueprints.
      • Les données doivent être enregistrées dans une base de données.
      • Les modifications de la base doivent être gérées avec des migrations.
      • Les formulaires doivent être réalisés avec Flask-WTF.
      • Les fichiers envoyés doivent être vérifiés et enregistrés correctement.
      • Les paramètres de l'application doivent être regroupés dans une configuration.
      • Les données locales et les informations sensibles ne doivent pas être publiées.
      • L'application doit pouvoir être préparée pour un déploiement.

    Conseils de réalisation

    Organisation de l'application

    • Séparer les principales fonctionnalités de l'application.
    • Prévoir un blueprint consacré aux pages générales, un pour les recettes et un pour les catégories.
    • Distinguer les responsabilités liées aux routes, aux formulaires, aux modèles et aux templates.
    • Conserver une structure commune pour toutes les pages grâce à un template principal.
    • Construire progressivement l'application avant d'ajouter la recherche, les filtres et l'envoi des images.

    Modèles et relation

    • Créer les modèles représentant les catégories et les recettes.
    • Déterminer les champs obligatoires, facultatifs ou uniques avant de créer la première migration.
    • Associer chaque recette à une catégorie avec une clé étrangère.
    • Prévoir une relation permettant d'accéder aux recettes appartenant à une catégorie.
    • Utiliser des noms explicites pour les modèles, leurs attributs et la relation qui les relie.
    • Prévoir une représentation lisible de chaque objet pour faciliter son identification.
    • Définir le comportement attendu lorsqu'une catégorie contient encore des recettes.

    Progression conseillée

    • Créer la structure générale de l'application et enregistrer les blueprints.
    • Configurer la base de données et les extensions utilisées par l'application.
    • Créer les modèles et appliquer les premières migrations.
    • Développer l'affichage des listes et des pages détaillées.
    • Ajouter les formulaires de création et de modification.
    • Ajouter la suppression avec une demande de confirmation.
    • Mettre en place la recherche et les différents filtres.
    • Ajouter l'envoi et l'affichage des photos.
    • Vérifier la configuration et préparer le projet pour son déploiement.

    Formulaires et validations

    • Prévoir un formulaire adapté aux recettes et un autre aux catégories.
    • Réutiliser autant que possible le même formulaire pour la création et la modification d'un objet.
    • Choisir les types de champs en fonction des données attendues.
    • Alimenter la liste des catégories à partir des catégories enregistrées dans la base de données.
    • Vérifier que le temps de préparation et l'estimation du coût contiennent des valeurs cohérentes.
    • Limiter les valeurs possibles pour le niveau de difficulté.
    • Vérifier que le nom d'une catégorie n'est pas déjà utilisé.
    • Afficher les erreurs à proximité des champs concernés.
    • Conserver les données déjà saisies lorsque le formulaire contient une erreur.

    Création et modification des données

    • Créer quelques catégories avant les premières recettes afin que l'utilisateur puisse les sélectionner dans le formulaire.
    • Utiliser les données validées par le formulaire avant de créer ou de modifier un objet.
    • Préremplir le formulaire lorsqu'une recette ou une catégorie est modifiée.
    • Enregistrer les modifications uniquement lorsque toutes les données sont valides.
    • Rediriger l'utilisateur après une création ou une modification réussie afin d'éviter un nouvel envoi du formulaire.

    Suppression des données

    • Afficher une page de confirmation avant toute suppression.
    • Indiquer clairement l'élément qui va être supprimé.
    • Empêcher la suppression d'une catégorie à laquelle des recettes sont associées.
    • Prévoir un message compréhensible lorsque la suppression est impossible.
    • Supprimer également la photo associée à une recette si elle n'est plus utilisée.

    Recherche et filtres

    • Afficher toutes les recettes avant d'ajouter les critères de sélection.
    • Récupérer les critères de recherche et de filtrage depuis les paramètres de l'adresse.
    • Construire progressivement la requête en ajoutant uniquement les filtres sélectionnés.
    • Permettre de combiner une recherche par nom avec un ou plusieurs filtres.
    • Prévoir une option permettant de réinitialiser les critères et de retrouver la liste complète.
    • Conserver les critères choisis dans le formulaire après l'affichage des résultats.
    • Afficher un message lorsque aucune recette ne correspond aux critères.

    Gestion des photos

    • Rendre l'ajout d'une photo facultatif.
    • Limiter les extensions autorisées aux formats d'image prévus par l'application.
    • Vérifier le fichier avant son enregistrement.
    • Générer un nom de fichier sûr afin d'éviter les noms invalides ou dangereux.
    • Éviter qu'un nouveau fichier remplace accidentellement une image existante.
    • Enregistrer uniquement le nom du fichier dans la base de données.
    • Prévoir une image ou une présentation par défaut lorsqu'une recette ne possède pas de photo.
    • Lors d'une modification, conserver l'ancienne photo si aucune nouvelle image n'est envoyée.

    Templates et navigation

    • Créer un template principal contenant la structure générale, le menu et les fichiers statiques communs.
    • Créer des templates distincts pour les listes, les pages détaillées et les formulaires.
    • Réutiliser le même template de formulaire pour la création et la modification lorsque cela est possible.
    • Permettre de passer facilement d'une catégorie à ses recettes et d'une recette à sa catégorie.
    • Rendre clairement visibles les actions d'ajout, de modification et de suppression.

    Configuration et sécurité

    • Regrouper les principaux paramètres de l'application dans une configuration dédiée.
    • Ne pas écrire directement une clé secrète définitive dans le code publié.
    • Configurer séparément l'adresse de la base de données et le dossier utilisé pour les images.
    • Ne pas publier la base de données locale, les fichiers envoyés par les utilisateurs ou les informations sensibles.
    • Ajouter les fichiers et dossiers concernés au fichier .gitignore.
    • Vérifier le comportement de l'application lorsque les données ou les fichiers attendus sont absents.

    Vérifications finales

    • Tester la création, la consultation, la modification et la suppression des deux types de données.
    • Tester les formulaires avec des données valides et invalides.
    • Vérifier qu'une recette reste toujours associée à une catégorie existante.
    • Tester séparément puis simultanément la recherche et les différents filtres.
    • Tester l'ajout d'une recette avec et sans photo.
    • Vérifier les liens entre les listes, les pages détaillées et les formulaires.
    • Tester le projet avec une base de données nouvellement créée.
    • Vérifier que le dépôt ne contient aucune donnée locale ou information sensible avant sa publication.
