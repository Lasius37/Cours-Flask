    Comprendre les relations

    Une application utilise souvent plusieurs modèles liés entre eux. Par exemple :

    • un auteur peut avoir écrit plusieurs livres
    • un livre a été écrit par un auteur

    Il serait possible d'enregistrer le nom de l'auteur directement dans chaque livre, mais cette solution entraînerait des répétitions. Une base de données relationnelle utilise plutôt deux tables :

    Table Données
    author Informations sur les auteurs
    book Informations sur les livres

    Chaque livre contient alors l'identifiant de son auteur.

    Auteurs (author)
    id name
    1 Jules Verne
    2 George Sand
    Livres (book)
    id title author_id
    1 Vingt mille lieues sous les mers 1
    2 La mare au diable 2
    3 Voyage au centre de la terre 1

    La colonne author_id permet de relier chaque livre à une ligne de la table author.

    Créer une relation un-à-plusieurs

    Une relation un-à-plusieurs associe un objet à plusieurs objets d'un autre modèle. Par exemple :

    • un auteur peut être associé à plusieurs livres
    • chaque livre est associé à un seul auteur

    Cette relation nécessite deux éléments :

    • une clé étrangère dans le modèle situé du côté « plusieurs » (livres)
    • des relations permettant de circuler entre les objets Python

    Ajouter une clé étrangère

    Les deux modèles peuvent être placés dans app/models.py. 

    from .extensions import db

class Author(db.Model):
    __tablename__ = "author"

    id = db.Column(...)

    name = db.Column(...)


class Book(db.Model):
    __tablename__ = "book"

    id = db.Column(...)

    title = db.Column(...)

    author_id = db.Column(
        db.Integer,
        db.ForeignKey("author.id"),
        nullable=False
    )

    La colonne author_id est placée dans le modèle Book, car plusieurs livres peuvent appartenir au même auteur.

    L'instruction db.ForeignKey("author.id") crée la clé étrangère :

    Elle indique que la valeur doit correspondre à la colonne id de la table author.

    Le nom utilisé dans ForeignKey est le nom de la table, et pas nécessairement le nom de la classe Python.

    Définir les relations entre les objets

    La clé étrangère crée le lien dans la base de données. La fonction db.relationship() permet ensuite d'utiliser ce lien directement avec les objets Python. 

    class Author(db.Model):
    __tablename__ = "author"

    id = db.Column(...)

    name = db.Column(...)

    books = db.relationship(
        "Book",
        back_populates="author"
    )


class Book(db.Model):
    __tablename__ = "book"

    id = db.Column(...)

    title = db.Column(...)

    author_id = db.Column(
        db.Integer,
        db.ForeignKey("author.id"),
        nullable=False
    )

    author = db.relationship(
        "Author",
        back_populates="books"
    )

    Deux propriétés sont ajoutées :

    Propriété Résultat
    author.books Liste des livres liés à l'auteur
    book.author Auteur lié au livre

    Le paramètre back_populates indique que les deux propriétés représentent les deux côtés de la même relation.

    db.relationship() ne crée pas une nouvelle colonne dans la table. Il crée une propriété utilisable dans le code Python.

    Créer des objets liés

    Utiliser la clé étrangère

    Un livre peut être associé à un auteur grâce à son identifiant. 

    author = db.session.get(
    Author,
    author_id
)

book = Book(
    title="Voyage au centre de la Terre",
    author_id=author.id
)

db.session.add(book)
db.session.commit()

    Utiliser la relation

    Il est également possible d'affecter directement l'objet auteur. 

    author = db.session.get(
    Author,
    author_id
)

book = Book(
    title="Voyage au centre de la Terre",
    author=author
)

db.session.add(book)
db.session.commit()

    SQLAlchemy renseigne alors automatiquement la valeur de author_id. Attention, il faut toutefois vérifier que l'auteur est déjà dans la base de données avant d'y ajouter le livre.

    Consulter les objets liés

    Retrouver l'auteur d'un livre

    book = db.session.get(
    Book,
    book_id
)
author = book.author

    Les propriétés de l'auteur deviennent accessibles : 

    book.author.name

    Retrouver les livres d'un auteur

    author = db.session.get(
    Author,
    author_id
)

books = author.books

    La propriété books contient une collection d'objets Book. Dans un template : 

    <h2>{{ author.name }}</h2>

<ul>
    {% for book in author.books %}
        <li>{{ book.title }}</li>
    {% else %}
        <li>Aucun livre enregistré</li>
    {% endfor %}
</ul>

    Modifier une relation

    Pour changer l'auteur d'un livre, on peut modifier sa clé étrangère : 

    book.author_id = new_author.id

db.session.commit()

    Il est également possible d'affecter directement le nouvel objet : 

    book.author = new_author

db.session.commit()

    Un objet peut aussi être ajouté à la collection d'un auteur : 

    book = Book(
    title="Un nouveau livre"
)

author.books.append(book)

db.session.commit()

    SQLAlchemy met alors à jour les deux côtés de la relation.

    Créer et gérer une relation plusieurs-à-plusieurs

    Dans une relation plusieurs-à-plusieurs, chaque objet peut être associé à plusieurs objets de l'autre modèle. Par exemple :

    • un livre peut appartenir à plusieurs catégories (ou genres littéraires)
    • une catégorie peut contenir plusieurs livres

    Une table d'association est alors nécessaire pour enregistrer les liens. 

    book_category = db.Table(
    "book_category",

    db.Column(
        "book_id",
        db.Integer,
        db.ForeignKey("book.id"),
        primary_key=True
    ),

    db.Column(
        "category_id",
        db.Integer,
        db.ForeignKey("category.id"),
        primary_key=True
    )
)

    Cette table ne représente pas un objet utilisé directement dans l'application. Elle enregistre seulement les associations entre les livres et les catégories. 

    class Book(db.Model):
    __tablename__ = "book"

    id = db.Column(...)

    title = db.Column(...)

    categories = db.relationship(
        "Category",
        secondary=book_category,
        back_populates="books"
    )


class Category(db.Model):
    __tablename__ = "category"

    id = db.Column(...)

    name = db.Column(...)

    books = db.relationship(
        "Book",
        secondary=book_category,
        back_populates="categories"
    )

    Le paramètre secondary indique la table d'association utilisée par la relation. Pour associer une catégorie à un livre : 

    book.categories.append(category)

db.session.commit()

    Pour retirer cette association : 

    book.categories.remove(category)

db.session.commit()

    Créer et gérer une relation un-à-un

    Une relation un-à-un associe un objet à un seul objet d'un autre modèle. Par exemple, un utilisateur peut posséder un seul profil détaillé.

    La clé étrangère peut être rendue unique avec le paramètre unique=True . 

    class Profile(db.Model):
    __tablename__ = "profile"

    id = db.Column(...)
    avatar = db.Column(...)

    user_id = db.Column(
        db.Integer,
        db.ForeignKey("user.id"),
        nullable=False,
        unique=True
    )

    user = db.relationship(
        "User",
        back_populates="profile"
    )

    Du côté de l'utilisateur, le paramètre uselist=False indique que la propriété ne contient pas une collection. 

    class User(db.Model):
    __tablename__ = "user"

    id = db.Column(...)
    password = db.Column(...)

    profile = db.relationship(
        "Profile",
        back_populates="user",
        uselist=False
    )

    La propriété user.profile renvoie alors un seul objet Profile, ou None.

    Erreurs fréquentes

    • Utiliser le nom de la classe dans ForeignKey : il faut indiquer le nom de la table et de la colonne.
    • Placer la clé étrangère du mauvais côté : dans une relation un-à-plusieurs, elle est généralement placée dans la table située du côté « plusieurs » .
    • Confondre ForeignKey et relationship : le premier crée le lien dans la base, le second facilite l'accès entre les objets .
    • Utiliser des noms différents dans back_populates : chaque valeur doit correspondre à la propriété définie dans l'autre modèle .
    • Créer un objet avec un identifiant étranger inexistant : la relation ne peut pas être établie correctement.
    • Oublier db.session.commit() : la création ou la modification de la relation n'est pas enregistrée .
    • Oublier secondary dans une relation plusieurs-à-plusieurs : SQLAlchemy ne connaît pas la table d'association.
    • Modifier les modèles sans adapter la base de données : les nouvelles colonnes et clés étrangères ne sont pas ajoutées automatiquement aux tables existantes .
