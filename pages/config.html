    Comprendre la configuration

    Une application utilise différents paramètres pour adapter son fonctionnement. Les pages précédentes ont déjà employé plusieurs paramètres :

    Paramètre Utilisation
    SECRET_KEY Signer les données sensibles et protéger les formulaires
    SQLALCHEMY_DATABASE_URI Indiquer l'emplacement de la base de données
    UPLOAD_FOLDER Indiquer le dossier des fichiers envoyés
    MAX_CONTENT_LENGTH Limiter la taille des requêtes

    Ces valeurs peuvent varier selon l'endroit où l'application est exécutée. Par exemple :

    • la base de développement peut être différente de celle utilisée après le déploiement
    • la clé secrète doit être propre à chaque installation
    • certains paramètres peuvent être activés uniquement pendant le développement

    La configuration permet donc de séparer les paramètres du reste du code de l'application.

    Utiliser app.config

    Chaque application Flask possède un objet config. Il se comporte comme un dictionnaire Python : 

    app.config["SECRET_KEY"] = "development-key"

app.config["MAX_CONTENT_LENGTH"] = 2 * 1024 * 1024

    Une valeur peut ensuite être récupérée avec sa clé : 

    max_size = app.config["MAX_CONTENT_LENGTH"]

    Les noms des paramètres de configuration sont généralement écrits en majuscules. Flask ne charge dans sa configuration que les variables dont le nom est écrit en majuscules lorsqu'elles proviennent d'un fichier Python.

    Définir les valeurs par défaut

    La méthode from_mapping() permet de définir plusieurs valeurs par défaut en une seule instruction. 

    app.config.from_mapping(
    SECRET_KEY="development-key",
    SQLALCHEMY_DATABASE_URI="sqlite:///database.db",
    MAX_CONTENT_LENGTH=2 * 1024 * 1024
)

    Cette écriture équivaut à plusieurs affectations avec app.config["..."].

    Les valeurs par défaut permettent à l'application de fonctionner immédiatement pendant le développement. Une valeur sensible utilisée par défaut doit être remplacée avant le déploiement.

    Créer un fichier de configuration

    Les paramètres généraux peuvent être regroupés dans un fichier config.py. 

    project/
│
├── app/
│   ├── __init__.py
│   ├── config.py
│   ├── extensions.py
│   └── models.py
│
├── instance/
└── run.py

    Dans app/config.py : 

    class Config:
    SECRET_KEY = "development-key"

    SQLALCHEMY_DATABASE_URI = "sqlite:///database.db"

    MAX_CONTENT_LENGTH = (
        2 * 1024 * 1024
    )

    La classe est ensuite chargée dans la fabrique : 

    from .config import Config


def create_app():
    app = Flask(__name__)

    app.config.from_object(Config)

    # Suite de l'initialisation

    return app

    La méthode from_object() charge les attributs en majuscules de la classe dans app.config. Ce fichier peut contenir les valeurs communes au projet, mais pas les secrets propres à l'installation lorsqu'il est ajouté au dépôt Git.

    Utiliser le dossier instance

    Le dossier instance peut contenir les données et paramètres propres à une installation. 

    project/
│
├── app/
├── instance/
│   ├── config.py
│   ├── database.db
│   └── uploads/
│
└── run.py

    Lors de la création de l'application, le paramètre instance_relative_config=True permet de charger les fichiers de configuration relativement à ce dossier. 

    def create_app():
    app = Flask(
        __name__,
        instance_relative_config=True
    )

    app.config.from_mapping(
        SECRET_KEY="development-key",
        SQLALCHEMY_DATABASE_URI="sqlite:///database.db"
    )

    app.config.from_pyfile(
        "config.py",
        silent=True
    )

    return app

    La méthode from_pyfile() charge ici le fichier instance/config.py. Le paramètre silent=True évite une erreur si le fichier n'existe pas. Les valeurs du fichier local remplacent les valeurs par défaut déjà chargées. Par exemple, dans instance/config.py : 

    SECRET_KEY = "une-cle-propre-a-cette-installation"

SQLALCHEMY_DATABASE_URI = "sqlite:///production.db"

    Ce fichier ne doit pas être ajouté au dépôt Git lorsqu'il contient des informations sensibles.

    Accéder à la configuration

    Dans la fabrique d'application

    L'objet app est directement accessible : 

    upload_folder = app.config["UPLOAD_FOLDER"]

    Dans une fonction de vue

    La fabrique ne doit pas être importée pour retrouver l'application en cours. Flask fournit current_app : 

    from flask import current_app


upload_folder = current_app.config["UPLOAD_FOLDER"]

    current_app représente l'application active pendant le traitement de la requête. Importer directement l'objet application dans les blueprints peut provoquer des imports circulaires. Il faut utiliser current_app lorsque l'application est créée avec une fabrique.

    Gérer la clé secrète

    La clé SECRET_KEY est utilisée pour signer certaines données produites par Flask et ses extensions. Elle intervient notamment dans :

    • les sessions
    • les messages temporaires
    • la protection CSRF des formulaires Flask-WTF

    Une clé de développement peut être écrite dans la configuration par défaut : 

    SECRET_KEY = "development-key"

    Pour une application déployée, elle doit être remplacée par une valeur longue et imprévisible, propre à l'installation. Python peut générer une valeur aléatoire : 

    python -c "import secrets; print(secrets.token_hex())"

    Attention, une clé secrète ne doit pas être publiée dans le dépôt Git, affichée dans une page ou envoyée au navigateur.

    Organiser la fabrique d'application

    La configuration doit être chargée avant l'initialisation des extensions qui l'utilisent. Une fabrique complète peut suivre cet ordre : 

    from pathlib import Path

from flask import Flask

from .config import Config
from .extensions import db, migrate


def create_app():
    app = Flask(
        __name__,
        instance_relative_config=True
    )

    # 1. Charger la configuration générale
    app.config.from_object(Config)

    # 2. Charger la configuration locale
    app.config.from_pyfile(
        "config.py",
        silent=True
    )

    # 3. Préparer les dossiers nécessaires
    upload_folder = Path(app.instance_path) / "uploads"

    app.config["UPLOAD_FOLDER"] = upload_folder

    upload_folder.mkdir(
        parents=True,
        exist_ok=True
    )

    # 4. Initialiser les extensions
    db.init_app(app)
    migrate.init_app(app, db)

    # 5. Importer les modèles
    from . import models

    # 6. Enregistrer les blueprints
    from .books import books_bp
    from .main import main_bp

    app.register_blueprint(main_bp)
    app.register_blueprint(books_bp)

    return app

    Lorsqu'une même clé est chargée plusieurs fois, la dernière valeur chargée remplace la précédente. L'ordre retenu est donc :

    • configuration générale
    • configuration propre à l'installation
    • création des dossiers nécessaires
    • initialisation des extensions
    • import des modèles
    • enregistrement des blueprints

    Protéger les fichiers locaux

    Les fichiers propres à une installation ne doivent pas être ajoutés au dépôt Git. Le fichier .gitignore peut contenir : 

    instance/
.venv/
__pycache__/
    Élément Contenu possible
    instance/ Base locale, fichiers envoyés et configuration locale
    .venv/ Environnement virtuel Python
    __pycache__/ Fichiers temporaires créés par Python

    Ajouter un fichier au .gitignore ne le retire pas de l'historique s'il a déjà été enregistré dans un commit.

    Erreurs fréquentes

    • Écrire tous les paramètres directement dans la fabrique : la configuration devient difficile à lire et à adapter .
    • Écrire une clé secrète de production dans un fichier partagé : toute personne ayant accès au dépôt peut la consulter .
    • Utiliser une clé secrète courte ou prévisible : les données signées par l'application sont moins bien protégées .
    • Donner un nom en minuscules à un paramètre chargé depuis un fichier Python : Flask ne l'ajoute pas à la configuration .
    • Charger la configuration après l'initialisation des extensions : certaines extensions peuvent utiliser des valeurs incorrectes .
    • Importer directement l'objet application dans un blueprint : cela peut provoquer un import circulaire .
    • Oublier instance_relative_config=True : le fichier passé à from_pyfile() n'est pas recherché relativement au dossier instance .
    • Utiliser silent=True pour un fichier obligatoire : l'absence du fichier est ignorée et peut passer inaperçue .
    • Ajouter instance/config.py au dépôt Git : des paramètres propres à l'installation peuvent être publiés .
    • Croire qu'un fichier ajouté au .gitignore est supprimé de l'historique : les anciennes versions restent présentes dans les commits .
