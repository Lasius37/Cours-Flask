    Comprendre l'envoi de fichiers

    Un formulaire peut permettre à l'utilisateur de déposer un fichier présent sur son appareil. Lors de l'envoi, le navigateur transmet à l'application :

    • le contenu du fichier
    • son nom d'origine
    • certaines informations comme son type déclaré

    L'application doit ensuite :

    • vérifier que le fichier est autorisé
    • sécuriser son nom
    • l'enregistrer dans un dossier prévu à cet effet
    • enregistrer son nom dans la base de données si nécessaire

    Il est généralement préférable de ne pas enregistrer directement le contenu du fichier dans la base de données. La base conserve seulement son nom.

    Configurer le dossier de destination

    Les fichiers envoyés peuvent être placés dans un dossier uploads situé dans le dossier instance. 

    project/
│
├── app/
├── instance/
│   ├── database.db
│   └── uploads/
│
└── run.py

    Dans la fabrique d'application : 

    from pathlib import Path

from flask import Flask


def create_app():
    app = Flask(__name__)

    upload_folder = Path(app.instance_path) / "uploads"

    app.config["UPLOAD_FOLDER"] = upload_folder

    upload_folder.mkdir(  # crée le dossier
        parents=True,  # et ses dossiers parents
        exist_ok=True  # s'il n'existe pas déjà
    )

    # Autres configurations

    return app

    Le dossier instance convient aux données propres à l'installation de l'application et ne doit pas être ajouté au dépôt Git. Il faut donc l'ajouter au fichier .gitignore.

    Limiter la taille des fichiers

    La taille maximale des requêtes contenant un fichier peut être limitée avec MAX_CONTENT_LENGTH.

    Pour autoriser au maximum 2 Mio : 

    app.config["MAX_CONTENT_LENGTH"] = 2 * 1024 * 1024

    Soit un total de 2 097 152 octets. Si la requête dépasse cette limite, Flask la refuse avec une erreur 413 Request Entity Too Large. Attention, la limite concerne la taille totale de la requête et pas uniquement celle du fichier.

    Enregistrer le nom du fichier

    Le modèle peut contenir une colonne destinée au nom du fichier enregistré.

    Dans app/models.py : 

    class Book(db.Model):
    id = db.Column(...)

    title = db.Column(...)

    cover = db.Column(
        db.String(255),
        nullable=True
    )

    La colonne est facultative afin qu'un livre puisse être enregistré sans image. La base contient uniquement le nom du fichier. Le fichier lui-même reste dans le dossier uploads/ configuré pour les envois.

    Créer le champ de fichier

    Flask-WTF fournit un champ et des validateurs adaptés aux fichiers. Dans app/books/forms.py : 

    from flask_wtf import FlaskForm
from flask_wtf.file import FileAllowed, FileField
from wtforms import StringField, SubmitField
from wtforms.validators import DataRequired


class BookForm(FlaskForm):
    title = StringField(
        "Titre",
        validators=[
            DataRequired()
        ]
    )

    cover = FileField(
        "Image de couverture",
        validators=[
            FileAllowed(
                ["jpg", "jpeg", "png", "webp"],
                "Formats autorisés : JPG, PNG ou WebP."
            )
        ]
    )

    submit = SubmitField("Enregistrer")

    Le validateur FileAllowed vérifie que l'extension du fichier appartient à la liste autorisée. Comme FileRequired n'est pas utilisé, l'image reste facultative. Pour rendre le fichier obligatoire : 

    from flask_wtf.file import FileRequired


cover = FileField(
    "Image de couverture",
    validators=[
        FileRequired(),
        FileAllowed(
            ["jpg", "jpeg", "png", "webp"]
        )
    ]
)

    Une extension autorisée ne garantit pas à elle seule que le contenu du fichier est réellement une image valide.

    Afficher le champ dans le formulaire

    Le formulaire HTML doit utiliser l'encodage multipart/form-data. 

    <form
    method="post"
    enctype="multipart/form-data"
>
    {{ form.hidden_tag() }}

    <div>
        {{ form.title.label }}
        {{ form.title() }}
    </div>

    <div>
        {{ form.cover.label }}
        {{ form.cover() }}

        {% for error in form.cover.errors %}
            <p class="error">{{ error }}</p>
        {% endfor %}
    </div>

    {{ form.submit() }}
</form>

    Sans enctype="multipart/form-data", le navigateur n'envoie pas le contenu du fichier. Le fichier validé est ensuite accessible avec form.cover.data.

    Enregistrer un fichier

    Après la validation du formulaire, le fichier peut être enregistré avec sa méthode save(). 

    from flask import current_app, redirect, render_template, url_for
from werkzeug.utils import secure_filename

from ..extensions import db
from ..models import Book
from . import books_bp
from .forms import BookForm


@books_bp.route(
    "/create",
    methods=["GET", "POST"]
)
def create_book():
    form = BookForm()

    if form.validate_on_submit():
        cover = form.cover.data
        filename = None

        if cover:
            filename = secure_filename(
                cover.filename
            )

            destination = (
                current_app.config["UPLOAD_FOLDER"]
                / filename
            )

            cover.save(destination)

        book = Book(
            title=form.title.data,
            cover=filename
        )

        db.session.add(book)
        db.session.commit()

        return redirect(
            url_for("books.list_books")
        )

    return render_template(
        "books/form.html",
        form=form
    )

    La fonction secure_filename() transforme le nom fourni par l'utilisateur afin de retirer les parties dangereuses ou incompatibles. Un nom comme ../../images/mon image.jpg peut par exemple devenirimages_mon_image.jpg. Le nom transmis par l'utilisateur ne doit jamais être utilisé directement pour construire un chemin sur le serveur.

    Créer un nom de fichier unique

    Deux utilisateurs peuvent envoyer des fichiers portant le même nom. Le second fichier risquerait alors de remplacer le premier. Une fonction peut générer un nom unique tout en conservant l'extension : 

    from pathlib import Path
from uuid import uuid4

from werkzeug.utils import secure_filename


def create_unique_filename(original_filename):
    safe_filename = secure_filename(
        original_filename
    )

    extension = Path(safe_filename).suffix.lower()

    return f"{uuid4().hex}{extension}"

    La propriété suffix récupère l'extension avec son point. Par exemple, le fichier transmis par l'utilisateur couverture.jpg devient 29df1c88d3544f4d879973bf7a0da64e.jpg. La route peut alors utiliser cette fonction : 

    if cover:
    filename = create_unique_filename(
        cover.filename
    )

    destination = (
        current_app.config["UPLOAD_FOLDER"]
        / filename
    )

    cover.save(destination)

    Le nom d'origine peut être affiché à l'utilisateur avant l'envoi, mais le serveur utilise son propre nom pour conserver le fichier.

    Afficher un fichier envoyé

    Les fichiers situés dans le dossier instance/uploads ne sont pas accessibles directement par une URL. Une route peut transmettre le fichier avec send_from_directory(). 

    from flask import current_app, send_from_directory


@books_bp.route("/uploads/<filename>")
def uploaded_file(filename):
    return send_from_directory(
        current_app.config["UPLOAD_FOLDER"],
        filename
    )

    Dans le template : 

    {% if book.cover %}
    <img
        src="{{ url_for(
            'books.uploaded_file',
            filename=book.cover
        ) }}"
        alt="Couverture de {{ book.title }}"
    >
{% endif %}

    La fonction send_from_directory() sert un fichier à partir d'un dossier défini par l'application. Cette route pourra plus tard être protégée si certains fichiers ne doivent être accessibles qu'à des utilisateurs autorisés.

    Remplacer un fichier

    Lors de la modification d'un livre, le champ de fichier reste généralement facultatif. Si aucun nouveau fichier n'est envoyé, l'ancien nom est conservé. 

    new_cover = form.cover.data

if new_cover:
    old_filename = book.cover

    new_filename = create_unique_filename(
        new_cover.filename
    )

    new_destination = (
        current_app.config["UPLOAD_FOLDER"]
        / new_filename
    )

    new_cover.save(new_destination)

    book.cover = new_filename

    if old_filename:
        old_path = (
            current_app.config["UPLOAD_FOLDER"]
            / old_filename
        )

        if old_path.exists():
            old_path.unlink()

    Le nouveau fichier est enregistré, puis son nom est enregistré dans la base de données. L'ancien fichier n'est supprimé qu'après la réussite de l'opération. Cela réduit le risque de perdre l'image existante si l'enregistrement du nouveau fichier échoue. Il faut ensuite enregistrer la modification du modèle db.session.commit().

    Supprimer un fichier

    La suppression d'un objet de la base ne supprime pas automatiquement le fichier enregistré sur le disque. Avant de supprimer un livre : 

    cover_path = None

if book.cover:
    cover_path = (
        current_app.config["UPLOAD_FOLDER"]
        / book.cover
    )

db.session.delete(book)
db.session.commit()

if cover_path and cover_path.exists():
    cover_path.unlink()

    La méthode unlink() supprime le fichier correspondant au chemin. Il faut vérifier que le chemin utilisé provient bien du dossier configuré par l'application et d'un nom enregistré par celle-ci.

    Erreurs fréquentes

    • Oublier enctype="multipart/form-data" : le navigateur n'envoie pas le contenu du fichier .
    • Utiliser directement le nom fourni par l'utilisateur : le nom peut contenir un chemin dangereux ou des caractères inadaptés .
    • Ne pas limiter les extensions autorisées : des types de fichiers non prévus peuvent être enregistrés .
    • Ne pas limiter la taille des requêtes : des fichiers trop volumineux peuvent consommer inutilement les ressources du serveur .
    • Réutiliser uniquement le nom d'origine : un fichier peut en remplacer un autre portant le même nom .
    • Enregistrer le fichier avant la validation du formulaire : un fichier associé à des données invalides peut rester sur le serveur .
    • Ajouter le contenu complet du fichier dans une colonne texte : la base de données ne contient pas le type de donnée attendu .
    • Supprimer un objet sans supprimer son fichier : des fichiers inutilisés restent sur le serveur .
    • Supprimer l'ancien fichier avant d'avoir enregistré le nouveau : l'application peut perdre le fichier existant si l'enregistrement échoue .
    • Placer les fichiers envoyés dans le dépôt Git : les données produites par les utilisateurs sont mélangées au code de l'application .
